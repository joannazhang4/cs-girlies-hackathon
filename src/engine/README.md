# On-device interaction engine

A TypeScript port of the Python interaction engine (`/interaction-engine`),
bundled into the app so that **medication data never leaves the device**.

## Why this exists

The tracker is end-to-end encrypted: `src/lib/crypto.ts` derives an AES-GCM key
from the user's password, and `src/data/storage.ts` writes only `{ciphertext,
iv}` to Supabase. The server never sees a medication name.

Sending the decrypted medication list to a backend for interaction checking
would have undone that — it would have meant the plaintext regimen leaving the
device on every render, which is precisely the data the encryption exists to
protect. So the engine runs here instead.

The whole database is ~250 drugs and ~2,348 interaction pairs — still well
under a megabyte. There was never a good reason for it to be a network
round-trip.

Drug/brand names come from standard US prescribing references (FDA drug
labels via DailyMed, RxNorm). Interactions are generated by applying
well-established, class-level interaction mechanisms (NSAID + anticoagulant
bleeding risk, SSRI + MAOI serotonin syndrome, opioid + benzodiazepine
respiratory depression, strong CYP3A4 inhibitor + statin myopathy risk, and
~60 other class-pair rules — see the `RULES` list used to generate
`interactionsDb.ts`) across the drug list. This is the same class-based
methodology real interaction checkers use, not a claim that every individual
pair was independently looked up in a clinical database — see the caveat
already in `interactionsDb.ts`.

## What this buys us

- **No network calls.** Interaction checking works offline, on a plane, with the
  backend down. Grep `src/engine` and `src/analytics` for `fetch(` — there are
  no hits, and that's the invariant the privacy claim rests on.
- **Synchronous.** `checkInteractions()` returns a value, not a promise, so
  existing `useMemo` call sites need no changes and there's no loading state.
- **No CORS, no second server, no ports to coordinate at demo time.**

## Layout

| File | Role |
|---|---|
| `data/drugAliases.ts` | brand/generic name table, keyed by `drug_id` |
| `data/interactionsDb.ts` | the 12 pairwise interactions |
| `similarity.ts` | port of Python's `difflib` (see below) |
| `normalization.ts` | raw name -> `drug_id` |
| `interactionEngine.ts` | pairwise checking, grouped by severity |
| `graph.ts` | `{nodes, edges}` for a force-directed visualization |

The analytics layer built on top lives in `src/analytics/`.

## The difflib port

`similarity.ts` is a faithful port of CPython's
`difflib.SequenceMatcher.ratio()` and `get_close_matches()`, not a generic
edit-distance library. This matters: the Python engine's tests pin specific
fuzzy behaviour (`"ibuprofin"` -> `ibuprofen` at cutoff 0.8), and a
Levenshtein-based library scores differently, which would silently change which
misspellings resolve.

It was verified to produce byte-identical ratios to CPython across the full
alias table plus 400 random string pairs, and the full engine was verified to
produce identical output to the Python engine across 300 generated regimens.

Two simplifications are safe here and are noted in the source: `isjunk` is
always null in our usage, and `autojunk` only engages at sequence length ≥ 200,
which drug names never reach.

## Keeping the two engines in sync

The Python service under `/interaction-engine` is still useful as a reference
implementation and test oracle. If you change the data:

1. Edit the Python JSON files **and** the TypeScript files in `data/`.
2. Run both test suites (`python -m pytest -q` and `npm test`).

The `data integrity` tests here assert that every `drug_a`/`drug_b` in
`interactionsDb.ts` exists in `drugAliases.ts` — the most common way to add an
interaction that can never fire.

## Adding a drug

```ts
// data/drugAliases.ts
gabapentin: { drug_id: 'gabapentin', generic_name: 'gabapentin', brand_names: ['neurontin'] },
```

## Adding an interaction

```ts
// data/interactionsDb.ts
{
  drug_a: 'gabapentin',
  drug_b: 'tramadol',
  severity: 'moderate',
  mechanism: 'Additive central nervous system depression.',
  evidence: 'Described in prescribing information for both agents.',
},
```

`mechanism` and `evidence` are not decoration — they are the only source
material the explanation layer is permitted to draw on. See the safety contract
at the top of `src/analytics/explain.ts`.
